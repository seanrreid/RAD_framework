## Failure-mode lookup (symptom to response)

| Symptom | Response | Check |
|---|---|---|
| Vague request grows into unintended work | Explicit intent, scope, exclusions, acceptance criteria | [S1](checks/intent-and-tasks.md#s1), [S2](checks/intent-and-tasks.md#s2) |
| Agent says "done" while requirements are missing | Evidence per requirement | [V2](checks/verification.md#v2) |
| Agent loads obsolete specs | Separate history from current knowledge | [K2](checks/knowledge-and-context.md#k2) |
| Prompt fails to constrain tool behaviour | Enforce in tools, proxies, infra | [E5](checks/environment-and-security.md#e5) |
| Code works but crosses module boundaries | Architecture review by people who know the system | [V8](checks/verification.md#v8), [A2](checks/architecture-and-quality.md#a2) |
| Lessons vanish after a successful change | Update knowledge; validate reusable skills | [K6](checks/knowledge-and-context.md#k6) |
| Review queue grows | Scale verification, route by risk, cap review rounds | [V1](checks/verification.md#v1), [P1](checks/people-and-organisation.md#p1), [V11](checks/verification.md#v11) |
| Cost runs away | Gateway caps, visibility, benchmarked model routing | [C1](checks/cost-and-budget.md#c1)-[C4](checks/cost-and-budget.md#c4) |
| Loop optimizes a bad measure | Freeze the measure | [V5](checks/verification.md#v5) |
| Agent exploits reachable authority | Enforce on indirect capabilities; Rule of Two | [E6](checks/environment-and-security.md#e6), [E8](checks/environment-and-security.md#e8) |
| Same mistake repeated across agents | Global memory plus deterministic linters | [K4](checks/knowledge-and-context.md#k4), [K7](checks/knowledge-and-context.md#k7) |
