# Architecture Directory

Architecture artifacts live here. Created by `/rad-design` (Draft mode),
approved by the architect, then consumed by `/rad-design` (Generate mode).

## Naming

```
[kebab-case-project-slug].md         ← architecture artifacts
```

## Status values

| Status | Meaning |
|--------|---------|
| `draft` | Generated by `/rad-design` — awaiting architect review |
| `approved` | Architect has reviewed and approved — ready for file generation |

## Lifecycle

```
/rad-design [slug]     → writes Status: draft
Architect reviews      → edits file, sets Status: approved
/rad-design [slug]     → detects approved, generates .claude/agents/ files
```

## What goes here

Architecture artifacts define the agent hierarchy, role assignments, scope
boundaries, and output contracts before any agent files are generated. Editing
this file is the correct way to change the architecture — not editing the
generated `.claude/agents/` files directly.

If the architecture needs to change after files have been generated, update
this artifact, set Status back to `draft`, get approval again, and re-run
`/rad-design`. Generated files will be overwritten.
