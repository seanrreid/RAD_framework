Issue-Title: Split RAD config out of CLAUDE.md: config is data the harness folds, not prose the model reads (part 1 of 2)

## Context

#87: CLAUDE.md is injected into every session, and its `## RAD Configuration` section is about 370 of its 488 lines. That section mixes **config data**, which scripts parse, with **env-knob reference**, which the model doesn't need. It also means role assignments and the scope map can't be self-protected, because plans legitimately edit CLAUDE.md prose. #87 is the foundation of the strategic arc: #85 (capability layers) and #71 (presets and overrides) both build on a config file.

**#87 is split into two plans, to fit the context budget:**
- **This plan (#87a)** creates `.rad/config.yml` and switches **every reader** to it in a hard cutover. After it merges, CLAUDE.md's config block is dead data that nothing reads.
- **#87b (next)** removes that block, moves the env-knob reference to `docs/configuration.md`, points the 10 skills (including `/rad-design`, the scope-map writer) at `rad config`, and updates `install.sh`, `UPGRADE.md` and the docs.

**Architect decisions (2026-09-30):**
- **Config file:** `.rad/config.yml` (YAML), read by the harness through the vendored `js-yaml`. Bash reads it through `node harness/cli.js config get <key>`, so there's one parser.
- **Hard cutover:** no fallback read from CLAUDE.md. A missing config names `rad config migrate`.
- **Self-protection:** `.rad/` joins the non-configurable self-protected set.

## Acceptance Criteria

1. `.rad/config.yml` schema (`version: 1`):
   - `platform` (github | gitlab | bitbucket | forgejo | manual)
   - `default_branch`
   - `roles` with `architect`, `developers` and `designers` as lists of identities (a lone string is accepted and normalized to a one-element list)
   - `agent_scope_map` as a list of `{ agent, type, reads, roles }`

   Unknown top-level keys are a validation **error** (fail-closed; later plans add keys explicitly). The loader never throws out of the CLI: it reports a named error.
2. `harness/config.js` exports `CONFIG_PATH` (`.rad/config.yml`), `loadConfig(root)`, `validateConfig(doc)` → errors[], `getConfigValue(doc, dottedKey)`, and `migrateFromClaudeMd(text)` → a config doc + warnings. `js-yaml` is imported lazily, matching the state store's constraint. Placeholder identities (`[your GitHub …]`) are rejected by validation, fixing the drift in `check-approval-integrity.sh`.
3. `rad config get <dotted.key>`:
   - **Scalar value:** printed on stdout, exit 0.
   - **List value:** one item per line, exit 0.
   - **Absent key:** exit **3**, no stdout.
   - **Missing config:** exit **1**, `rad: no .rad/config.yml — run 'rad config migrate'`.
   - **Invalid config:** exit **1**, naming each error.
   - **Usage error:** exit 2.
4. `rad config validate` → exit 0 with `✓ .rad/config.yml valid`, or exit 1 listing the errors. `rad config migrate [--from CLAUDE.md] [--force]` writes `.rad/config.yml` from CLAUDE.md's RAD Configuration block:
   - It refuses if the file exists unless `--force`.
   - It never edits CLAUDE.md, and prints the block lines to remove.
   - It exits 1 when a required key can't be found.
   - Running it on this repo's CLAUDE.md produces a config equal to the committed `.rad/config.yml`.
5. **Readers switch, with no CLAUDE.md fallback:**
   - **`get-default-branch.sh`:** reads `default_branch` via `rad config get`, falling back to `main` only on an **absent key** (exit 3). A missing or invalid config is an error: exit 1 with the reason. The optional path argument becomes the repo root.
   - **`detect-platform.sh`:** reads `platform` via `rad config get`. An absent key, or a missing config (the pre-install case), means URL detection with a notice. An invalid value means `manual` + a warning (unchanged semantics).
   - **`check-role.sh`:** reads `roles.<role>`.
   - **`check-approval-integrity.sh`:** reads `roles.architect` (`RAD_ARCHITECT_OVERRIDE` still first). The placeholder filter now comes from validation.
   - **`lint-agent-files.sh`:** reads `agent_scope_map` for the scope-map ↔ agent-files sync check.
   - **`harness/cli.js` and `git-state-store.js`:** pass the config path, not the CLAUDE.md path, to `check-role.sh` / `get-default-branch.sh`. The `claudeMd` option becomes `configPath`.
   - Every script guards its inputs and passes the shell-safety lint.
6. **Behavior parity:** for this repo, every reader returns the same value from `.rad/config.yml` as it did from CLAUDE.md (`default_branch` main, `platform` github, architect `sean@torchcodelab.com`, the same scope-map rows). This is verified by one scripted before/after comparison, recorded in the commit body.
7. **Fixtures and tests:** all 11 fixtures write `.rad/config.yml` in place of (or alongside) their CLAUDE.md config lines. `cli.test.js`, `approval-authority-recording.test.js` and `portable-process-memory.test.js` are updated for the config path. New tests cover `harness/config.js` (schema, get, migrate) and the `rad config` verbs.
8. `RAD_SELF_PROTECTED_PATTERN` gains `^\.rad/`. The CLAUDE.md Self-Protected Paths literal and the `docs/invariants.yaml` `self-protected-paths-flagged` entry are updated, and `scripts/test-lint-plan.sh` gets a `.rad/config.yml` case. A new registry invariant, `rad-config-is-data`, asserts that roles and the scope map are read from `.rad/config.yml` only. It's anchored on `harness/config.js` and `check-role.sh`, with `evals` / `not_evalable` set honestly.
9. This repo's `.rad/config.yml` is committed. CLAUDE.md's config lines are **left in place** (dead data, removed in #87b), with a one-line comment above the block: `<!-- authoritative config now lives in .rad/config.yml (#87); this block is removed in #87b -->`.
10. Every suite stays green: harness tests, evals, every shell test under both shells, `lint-shell-safety`, `lint-invariants`, `lint-agent-files` (in CI), and the replay check.

## Program Design

### 1. Schema (`.rad/config.yml`)

```yaml
version: 1
platform: github
default_branch: main
roles:
  architect: [sean@torchcodelab.com]
  developers: []
  designers: []
agent_scope_map:
  - { agent: quality-reviewer, type: reviewer, reads: "current diff or specified files, CLAUDE.md conventions", roles: [architect, developer, designer] }
  # … one row per agent, migrated from the CLAUDE.md table
```

### 2. Access

```
harness:  loadConfig(root) → doc   (lazy js-yaml; errors named)
bash:     node "$ROOT/harness/cli.js" config get <key>   → stdout; exit 0 found / 3 absent / 1 missing|invalid / 2 usage
readers:  get-default-branch.sh  → default_branch (absent → main; missing/invalid config → exit 1)
          detect-platform.sh     → platform (absent or no config → URL detection)
          check-role.sh          → roles.<role>
          check-approval-integrity.sh → roles.architect (after RAD_ARCHITECT_OVERRIDE)
          lint-agent-files.sh    → agent_scope_map
```

### Reminders
- **Hard cutover.** No reader falls back to CLAUDE.md. A missing config names `rad config migrate`. The one exception is `detect-platform.sh`, which treats a missing config as "no setting" (it runs during install).
- **Parity first.** Values read after the cutover must equal the values read before, for this repo (AC#6).
- **Keep js-yaml lazy** in any module the state store imports.
- **Shell-safety lint and portability** (bash 3.2) for every changed script. Bash spawns node for `config get`, and `ROOT` is resolved from the script's own directory.
- **Re-lint** every committed plan with main's lint vs this branch's lint (temp copies): adding `.rad/` to the self-protected set must add at most advisory warnings.
- **Long final checks** exceed the 2-minute foreground timeout. Run them with `run_in_background`.

## Risks
- **Hard cutover breaks unmigrated installs.** Any repo without `.rad/config.yml` gets named errors from `get-default-branch.sh`, `check-role.sh`, `rad approve`, and so on. That's intended; `rad config migrate` is the fix, and #87b documents the upgrade. This repo migrates in this PR.
- **Node spawn per bash read.** Each `config get` spawns node. That's acceptable at today's call counts; `get-default-branch.sh` is called a few times per verb.
- **Intermediate state.** Between #87a and #87b, skills still tell the model to read roles and the scope map from CLAUDE.md. That data is identical (kept as dead data) until #87b rewires them.
- **Self-protected paths:** `harness/`, `scripts/` and now `.rad/` trigger advisory lint warnings by design.
