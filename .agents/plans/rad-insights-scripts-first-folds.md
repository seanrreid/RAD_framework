## Context
`.rad/skills/rad-insights/SKILL.md` is 1509 lines because Steps 4c, 4e and 4g embed
`node --input-type=module -e` fold snippets in the prompt, so the model re-runs ~330 lines
of inline code every invocation. Steps 3d (`scripts/report-ledger-staleness.sh`) and 4j
(`harness/human-corrections.js`) already show the scripts-first shape: a module does the
deterministic fold and prints a compact section, and the skill only runs it and reads the
output. This plan applies that shape to the three largest folds. It brings the skill to
roughly 1180-1260 lines; reaching ~400-500 needs follow-up plans for 4f-4f4, 4h and 4i.

## Scope
| In scope | Out of scope |
|---|---|
| Fold logic of Steps 4c, 4e, 4g moves to harness modules | Steps 4d, 4f, 4f2, 4f3, 4f4, 4h, 4i (follow-up plans) |
| Skill runs each module and reads its output | The Step 5 report template and judgment prose |

| Regenerated `.agents/skills` and `.claude/commands` outputs | A new `rad` CLI subcommand |

## Acceptance Criteria
1. Each of the Step 4c, 4e and 4g folds is a `harness/` ES module that exports pure build/format functions and prints its section when run directly (`node harness/<module>.js`), honoring `RAD_STATE_DIR` (default `.agents/state`) and `RAD_FINDINGS_FILE` (default `.agents/findings.jsonl`); read-side only, importing existing folds from `harness/events.js` and the task parser from `harness/plan-tasks.js` rather than copying them.
2. Parity: for each fold, the new module's output is byte-identical to golden output captured from the old inline snippet (at the base commit) on every fixture under `harness/test/fixtures/insights/` plus an empty state dir, and matches the old snippet on a read-only run against the live `.agents/state/*/events.jsonl` logs.
3. Each module has a test for each named edge case: missing state dir, empty `events.jsonl`, missing field on an event, zero counts, and a non-array field; each case's expected behavior matches the old snippet and is asserted explicitly.
4. In `.rad/skills/rad-insights/SKILL.md` the three snippets are replaced by run-and-read instructions; the interpretation prose, the Step 5 template and the strings pinned by `harness/test/skill-bodies.test.js` (`.agents/findings.jsonl`, `scripts/draft-insights-plan.sh`) are unchanged; the Step 5 template is byte-identical.
5. The skill source shrinks from 1509 to 1260 lines or fewer.
6. `node harness/cli.js generate --check` passes, `npm test --prefix harness` passes, and `scripts/verify-all.sh` passes (including function-length and shell-safety lints).

## Program Design
Key signatures (each module; all functions kept under ~40 lines):
- `buildReliability(stateDir) -> rows` / `formatReliability(rows) -> string` (4c)
- `buildBlockedFiles(stateDir, plansDir) -> rows` / `formatBlockedFiles(rows) -> string` (4e)
- `buildPromptSurfaces({ failReasons, blockedReasons, attemptOutcomes }) -> rows` / `formatPromptSurfaces(rows) -> string` (4g), with `PROMPT_SURFACE_MAP` as one named table at the top of the file.

Control flow: skill Step 4x runs `node harness/insights-<x>.js` -> module reads the state dir ->
calls `harness/events.js` folds (`outcomeCounts`, `failReasonCounts`, `blockedReasonCounts`,
`attemptOutcomeCounts`) and `harness/plan-tasks.js` -> `format*` prints the section ->
skill reads stdout and applies the unchanged interpretation prose. A non-zero exit means the
skill reports stderr verbatim and does not retry (Step 3d convention).

File-tree diff: add 3 modules under `harness/`, 3 tests under `harness/test/`, 1 golden fixture;
modify the skill source and its two generated outputs.
