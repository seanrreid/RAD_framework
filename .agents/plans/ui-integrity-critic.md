## Context
RAD ships two generic reviewers, `quality-reviewer` and `accessibility-reviewer`, sourced in `.rad/agents/`, generated by `rad generate`, and dispatched by `/team:rad-review`. `docs/candidate-playbook-critic-rubric.md` proposes rubric-backed critics; none exists yet. This plan ships the first, `ui-integrity-reviewer` (decorative UI, edge-input audit, sibling sweep, assertion audit), advisory only, so the note can later be promoted to a `critic--<slug>` playbook from a real diff.

## Scope
| In scope | Out of scope |
|---|---|
| `ui-integrity-reviewer` agent source, scope-map row, `/team:ui-integrity-review` command (Claude and Codex) | Promoting the playbook or adding `critic` to `playbook_kinds:` |
| Gated dispatch step in `/team:rad-review` and findings persistence | Blocking mode, CI critic workflow, path router / preflight |
| Eval fixtures, install-test and doc updates for the new reviewer | Changes to `harness/` logic (`findings.js`, `review.js`, `generate.js`) |

## Acceptance Criteria
1. `.rad/agents/ui-integrity-reviewer.md` exists as a read-only reviewer (`tools: Read, Bash`, codex `sandbox_mode: read-only`) whose report ends with a `rad-findings` block using the categories `decorative-ui`, `hardcoded-display-data`, `edge-input`, `sibling-sweep`, `assertion-audit`, and shows the sibling sweep (pattern, instances, covered or not).
2. `.rad/config.yml` `agent_scope_map` has a `ui-integrity-reviewer` row and `scripts/lint-agent-files.sh` passes.
3. `/team:ui-integrity-review` exists for Claude and as a Codex skill, generated from `.rad/skills/ui-integrity-review/`, and runs standalone on the current diff or named files.
4. `/team:rad-review` runs the new reviewer only when changed files include frontend sources; with none it skips with a stated reason and the review otherwise behaves as before. Its findings are persisted to `.agents/findings.jsonl` by the existing Step 7 with `reviewer: ui-integrity-reviewer`.
5. The reviewer is advisory: it never edits files, never writes `findings.jsonl`, and its output cannot approve a plan or change severity routing.
6. `rad generate` output is committed and the `generated-drift` check passes.
7. Eval fixtures cover at least one clean control and one defect case per rubric class, and the reviewer eval tests pass.
8. `bash scripts/verify-all.sh` passes.

## Program Design
Findings record (unchanged shape, new reviewer name and categories):
`{type:"finding", reviewer:"ui-integrity-reviewer", priority, category, file, line, issue, wcag:null}`.
Flow: `/rad-review` → changed files include frontend sources? → `node harness/cli.js review ui-integrity-reviewer --base "$BASE"` (or sub-agent) → `rad-findings` block → Step 7 appends to `.agents/findings.jsonl`. `/rad-insights` counts categories as free strings, so no change is needed there.

- Hand-edited generated files would fail `generated-drift`.
