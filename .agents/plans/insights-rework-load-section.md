## Context
Plan 1 of 2 (`rad/post-merge-rework-and-review-load`) adds the pure folds in
`harness/delivery-metrics.js` and the plain-git reader in `harness/delivery-history.js`. This plan
surfaces their output in `/rad-insights` as a new Step 4i and a "Rework and Gate-2 Load" report
section, modelled on Step 4h ("Cycle time, human touches and tokens"). It also regenerates the
skill copies and adds a line to the guide docs. **It depends on plan 1 being merged first**, since
Step 4i imports those modules. Delivering it earlier would make Step 4i's import fail.

The section is information only. Following the Spotify post the issue cites, it reports trends and
sample sizes with no thresholds, so the team can see whether PR size is a leading indicator before
anyone tunes for it.

## Acceptance Criteria
1. The skill source has a Step 4i after Step 4h. It resolves `default_branch` via `node harness/cli.js config get default_branch`, loads event histories the same way Step 4h does, and imports `readDeliveryHistory` and the folds with `node --input-type=module -e`. It prints JSON `{load, rework, trends:{reworkRate, prSize, reviewLatency}, unresolved, windowDays}`. On a reader error it reports the error and omits the section, and it never stops the report.
2. The report template has a "### Rework and Gate-2 Load" section after "Cycle Time and Human Touches", containing:
   - a per-feature table: rework rate, reworked/total files, weighted rework, window complete?, files and lines changed, opened→merged;
   - three trend lines, each showing `n`;
   - the window in days and its source (`RAD_REWORK_WINDOW_DAYS`, default 14);
   - the verbatim framing line "Reporting only — no target or threshold applies to these values."

   The section is omitted when there are no deliver merges.
3. The Rules list gains two lines: these values are never read to block, warn or gate; `RAD_REWORK_WINDOW_DAYS` parses via `Number.parseInt`, and unset/0/NaN/negative falls back to 14.
4. `.claude/commands/shared/rad-insights.md` and `.agents/skills/rad-insights/SKILL.md` are regenerated by `rad generate`, not hand-edited, and carry Step 4i.
5. `docs/daily-workflow.md` and `docs/architect-guide.md` describe the section as information only. Running the Step 4i snippet in this repo prints JSON that includes this repo's recent deliver merges (e.g. PR #284). `scripts/verify-all.sh` passes.
