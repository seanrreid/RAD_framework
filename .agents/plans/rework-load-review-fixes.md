## Acceptance Criteria
1. `readDeliveryHistory` throws an error naming the malformed record when `git log` output has a record without the `\x03` header terminator. A test in `harness/test/delivery-history.test.js` drives this through an injected `sh`; `parseLog` stays unexported.
2. A test in `harness/test/delivery-metrics.test.js` covers this case: a deliver merge changes `a.js`, a later deliver merge with `a.js` in its `scopedFiles` renames it to `a2.js`, and a later direct commit edits `a2.js`. The expected result is `reworkedFiles: 1` and `reworkCommits: 1`: the planned rename is not rework, and the later edit is.
3. The skill's report template names the source array for every per-row token in both "Reworked / files" and "Files / lines": `rework.reworkedFiles`/`rework.files` versus `load.files`/`load.linesChanged`. A line before the table says which array each column comes from.
4. The skill documents that a merged `load` row's `pr` can be `null` (no `(#N)` in the subject), and the template renders it as "n/a" rather than `#null`.
5. `.claude/commands/shared/rad-insights.md` and `.agents/skills/rad-insights/SKILL.md` are regenerated by `rad generate`, not hand-edited.
6. `.agents/findings.jsonl` gains exactly the 8 staged records (6 findings + 2 cycles from the 2026-10-16 review of `post-merge-rework-and-review-load` and `insights-rework-load-section`), appended with no existing line changed. `scripts/verify-all.sh` passes, including `events-append-only`.
