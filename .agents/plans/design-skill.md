## Context
`/architect:rad-design` (.claude/commands/architect/rad-design.md, 328 lines) is a hand-written Claude command. It reads a research artifact, drafts an agent hierarchy into `.agents/architecture/<slug>.md`, and gets inline approval through the existing `node harness/cli.js architecture-approve <slug>` (an `architecture-approved` event). It then starts one Haiku sub-agent per agent to write `.claude/agents/<name>.md` directly, and **prints** the `agent_scope_map` block and the `git add`/`commit` lines for the architect.

Its Claude-only parts:
- `$ARGUMENTS` (L28, L30);
- the Haiku sub-agent fan-out (L216-268);
- direct `.claude/agents` output;
- printed `git add`/`git commit` lines (L307-308);
- a `cp … ~/.claude/commands/` hint (L310).

`.rad/agents` sources plus `rad generate` already produce `.claude/agents/<name>.md` and Codex `.codex/agents/<name>.toml` (generate.js `renderAgent`, L340-351). The two reviewer agents use this path.

The user decided on 2026-10-08:
- **3f direction:** the skill writes `.rad/agents/<name>.md` sources and runs `rad generate`.
- **Q1:** this repo's 27 hand-written agents move to sources in a separate plan, **3f-ii**.
- **Q2:** the scope map stays **printed for the architect to paste**, with no new config-writing verb. The skill then has them run `config validate` and the agent lint.

## Acceptance Criteria
1. **The skill source.** `.rad/skills/rad-design/SKILL.md` has frontmatter `name: rad-design`, the existing description (reworded to say it writes `.rad/agents` sources and runs `rad generate`), and `targets: { claude: command:architect/rad-design, codex: skill, codex_implicit: false }`. The body keeps every step, the architecture-artifact template, the approval flow (`node harness/cli.js architecture-approve`, including the proxy flags) and the rules. It changes only:
   - **Input:** `$ARGUMENTS` becomes `{{args}}`.
   - **Step 6:** for each approved agent, write `.rad/agents/<kebab-name>.md`. Delegate per agent when the tool can run sub-agents, otherwise write them inline, reusing rad-plan's wording.
     - The frontmatter template is name, description, model, tools, roles and purpose, plus `codex: { sandbox_mode: read-only }` for context-tool agents (tools within Read/Grep/Glob).
     - The model IDs and Claude tool names inside the **agent template** stay, because the agent files require them (`AGENT_REQUIRED`, and lint-agent-files.sh's context-tool rules).
   - **New step after Step 6:** run `node harness/cli.js generate`. It produces `.claude/agents/<name>.md` and `.codex/agents/<name>.toml`, and refuses to overwrite a hand-written file of the same name. Report a refusal and stop.
   - **Step 7 is unchanged:** print the `agent_scope_map` block for the architect to paste. After pasting, they run `node harness/cli.js config validate` and `scripts/lint-agent-files.sh`.
   - **Step 8:** the printed git lines become an instruction for the architect to review and commit `.rad/agents/`, the generated outputs, the architecture artifact and `.rad/config.yml`. It runs no git commands. The `cp … ~/.claude/commands` hint is dropped.
   - **Wording:** "Claude Code ignores vague descriptions" becomes tool-neutral ("agents with vague descriptions are not selected").
   - The body passes skill-bodies' `FORBIDDEN_PATTERNS`.
2. **Generated outputs.** `node harness/cli.js generate` replaces `.claude/commands/architect/rad-design.md` with a marked, generated file. It writes `.agents/skills/rad-design/SKILL.md` and `.agents/skills/rad-design/agents/openai.yaml` (`allow_implicit_invocation: false`). `generate --check` exits 0.
3. **Registry tests.** In harness/test/skill-bodies.test.js:
   - `rad-design` goes in `TOOL_NEUTRAL_SKILLS` and `EXPLICIT_ONLY_SKILLS`;
   - `CLAUDE_COMMAND_ROLE['rad-design'] = 'architect'`;
   - `REQUIRED_COMMANDS['rad-design'] = ['node harness/cli.js architecture-approve', 'node harness/cli.js generate', '.rad/agents/']`.

   In scripts/test-install-harness.sh, `SLICE_SKILLS` gains rad-design, plus an openai.yaml assert.
4. **Docs.**
   - docs/rad-tool-portability.md: the rad-design row reads `generated (#186 part 3f)`, with Deps `rad CLI, $ARGUMENTS`. The agent-source spec (~130-135) lists `purpose` and `codex.sandbox_mode`. The 27-agent row (~76) notes the migration is planned in 3f-ii.
   - docs/architect-guide.md (~60-100, ~140-145): rad-design writes `.rad/agents` sources and runs `rad generate`. Agent edits go to the source, followed by `rad generate`, never to `.claude/agents` directly. The commit list includes `.rad/agents/` and `.codex/agents/`.
