## Context
`rad deliver` opens its PR with placeholder text (`SCRIPT_ARGS`, cli.js:293-299): title `Deliver: <slug>` and body `RAD deliver: N wave(s) complete`. In the prose `/rad-deliver` (step 10), the agent writes the body by hand. Part 3 makes `rad deliver` the only deliver path, so it must build a useful body itself, the same way every time.

Decisions:
- **Part 3, earlier:** the body holds the plan; the event log's tasks, commits and concerns; the commit list; Tests to Write marked present or missing; check-scope; and `Issue: #N` with no `Closes`.
- **3b-iii Q1 (2026-10-07):** the title is `Deliver: <plan "# Plan:" heading>`, falling back to the slug.
- **3b-iii Q2:** the `already delivered` message gets no PR URL.
- **3b-iii Q3:** a read-only `rad pr-body <feature>` command prints the same title and body.

## Acceptance Criteria
1. **The pure builder.** `buildPrBody({ feature, planPath, planText, history, commits, tests, scope })` returns `{ title, body }`. It does no I/O and no clock reads, so the same inputs always give byte-identical output.
   - **Title:** `Deliver: <heading>`, where the heading comes from `# Plan: <heading>`. With no heading the title is `Deliver: <feature>`.
   - **Body**, in this order:
     1. `Plan: \`<planPath>\``
     2. `Issue: #N` from `planIssueNumber`, omitted when there's none. **Never** a closing keyword.
     3. `## Waves`: one `### Wave N` per wave, in number order, from the **last** `wave-attempt` with `outcome: 'success'`. Each task is one line: `- <icon> <title> — <commit>`, then ` — concern: <concern>` when the concern is not `—`. The icons are ✓ `complete` and ⚠ `done_with_concerns`. A passing attempt with no `tasks` renders `- (no task details recorded)`. A wave with no passing attempt renders `- (no passing attempt recorded)`.
     4. `## Commits`: `- <short hash> <subject>`, oldest first, capped at `MAX_COMMITS` (100) with a `- … and N more` line. An empty list renders `- (none)`.
     5. `## Tests to Write`: `- ✓ <path>` or `- ✗ <path> (missing)`, plus `- ? <raw line> (unresolvable)` for lines that don't parse. With no section it renders `- (none declared)`.
     6. `## Checks`: `- check-scope: passed`, or `- check-scope: N violation(s)` followed by the listed files, or `- check-scope: unavailable (<reason>)`.
     7. A footer: `Generated by rad deliver from the plan and the event log.`
   - **Agent-written text** (task titles and concerns) has closing-keyword references neutralized: `fixes #12` → `fixes issue 12`. This stops a WAVE_RESULT line from auto-closing an issue or tripping `open-pr.sh`'s closing-link check. It uses the same pattern as `CLOSING_KEYWORD_RE`, case-insensitive. Line breaks inside agent text are collapsed to spaces.
2. **The folds** are exported and pure:
   - `lastPassingTasks(history)` → `Map<wave, tasks|null>`;
   - `testsToWritePaths(planText)` → `[{ path } | { unresolvable: line }]`. It ports the bash rule from check-tests-present.sh:25-64: lines starting `- ` in `## Tests to Write` up to the next `## `; the path is the text after the last `— `; backticks and one trailing `(…)` are stripped; an empty path, `[file]` or an annotation-only `(…)` is unresolvable;
   - `neutralizeClosingKeywords(text)`.
   - Non-array or non-string input throws `TypeError`.
3. **Deliver wiring.** The `open-pr.sh` entry in `SCRIPT_ARGS` passes the built `title` and `body`; `--head`, `--no-draft` and `--label` are unchanged. `makeScriptCtx` gains a lazy `prBody()` that reads the inputs when the spine calls `open-pr.sh`:
   - the plan text from `<root>/.agents/plans/<f>.md`;
   - `state.history(feature)`;
   - commits from `git log --reverse --format=%h %s origin/<base>..HEAD` in root;
   - each test path's presence via `git cat-file -e HEAD:<path>` in root;
   - `scope: { passed: true }`, because the spine runs `open-pr.sh` only after `check-scope.sh` exits 0.
   - **Failure:** if an input read fails, the builder still runs with that section marked unavailable (for example `- (commit list unavailable: <reason>)`). A failure to build the body never blocks the PR, and the reason appears in the body.
4. **`rad pr-body <feature> [--branch <b>] [--base <b>]`** is read-only.
   - **Inputs:** the plan and the event log come from the branch tip. The branch defaults to `rad/<f>`; the plan via `git show <branch>:.agents/plans/<f>.md`, the log via `readBranchTipHistory`. Commits come from `git log origin/<base>..<branch>`, test presence from `git cat-file -e <branch>:<path>`. The base defaults to `readDefaultBranch`, then `main`.
   - **Scope:** it runs `scripts/check-scope.sh <tmp>/<f>.md <branch> <base>` on a temporary copy of the branch-tip plan, through `readScope`, which digest.js exports for this.
   - **Output:** stdout gets `<title>`, a blank line, then the body. The exit codes are:

     | Exit | When |
     |---|---|
     | 0 | Success |
     | 2 | Bad arguments, an unsafe feature name, or a plan missing at the branch tip (message plus usage) |
     | 1 | A malformed event log |

   - **No side effects:** it fetches nothing, writes nothing outside the OS temp dir, and removes its temp file.
   - **Registration:** it is listed in `SUBCOMMANDS`, so `rad --help` shows it.
5. **Tests.**
   - `harness/test/pr-body.test.js` covers:
     - an exact-string snapshot of a two-wave body;
     - the title with and without a heading;
     - the issue present and absent (and never `Closes`);
     - a retried wave uses the last passing attempt;
     - `tasks` absent, and a wave with no passing attempt;
     - the concern shown or hidden;
     - the commit cap, and an empty commit list;
     - tests present, missing and unresolvable, and no section;
     - all three scope shapes;
     - closing-keyword neutralization;
     - multi-line agent text collapsed;
     - `TypeError` on bad input;
     - the same inputs giving identical output.
   - cli.test.js:
     - the real-deliver argv test (1409-1432) now asserts the built title and that the body contains `Plan:`, `## Waves` and `## Checks`;
     - new `rad pr-body` cases against a real repo (plan and log committed on `rad/<f>`): success output, usage exit 2, plan missing at the tip exit 2, malformed log exit 1, and `--help` lists `pr-body`.
6. **Docs.**
   - `docs/rad-cli.md` `### rad deliver` finish-phase step 2 describes the generated title and body.
   - A new `### rad pr-body` section covers usage, inputs, output, exit codes and that it's read-only.

## Program Design

**Signatures**
```js
// harness/pr-body.js
export function buildPrBody({ feature, planPath, planText, history, commits, tests, scope }) // → { title, body }
// commits: [{ hash, subject }] | { unavailable: reason }
// tests:   [{ path, present } | { unresolvable: line }] | { unavailable: reason }
// scope:   { passed: true } | { passed: false, violations: string[] } | { unavailable: reason }
export function lastPassingTasks(history)        // → Map<number, Array|null>
export function testsToWritePaths(planText)      // → [{ path } | { unresolvable }]
export function neutralizeClosingKeywords(text)  // → string
// harness/plan-commit.js
export function planHeading(text)                // → string | null
```

**Call stacks**
```
rad deliver … spine → sh('scripts/open-pr.sh') → SCRIPT_ARGS[open-pr](c) → c.prBody()
  → gather(planText, history, commits, tests) → buildPrBody → ['--title', t, '--body', b, …]
rad pr-body <f> → parse → git show plan → readBranchTipHistory → git log / cat-file → readScope(tmp plan)
  → buildPrBody → stdout
```

## Risks
- **The PR body is now generated, not hand-written.** A reviewer loses the agent's free-form summary but gains a complete, checkable one. The PR can still be edited by hand after it opens.
- **Agent text goes into the PR.** Closing keywords are neutralized and line breaks collapsed. Other markdown in a concern renders as-is, which is acceptable for a one-line concern.
- **Body size:** commits are capped at 100. With ~15 waves of tasks the body stays well under GitHub's 65,536-character limit and the OS argv limit.
- **`rad pr-body` reads local refs only.** If `origin/<base>` is stale locally, the commit list may include commits already on main. The docs advise a `git fetch` first.
- **Self-protected paths** (`harness/`): this plan needs architect review by design.

## Issue Gaps
- **Assumption — the body format** is the one in AC#1. The order and icons are a judgment call, pinned by the snapshot test.
- **Assumption — closing keywords are neutralized by rewriting `#N` to `issue N`,** rather than escaping. Rewriting is guaranteed not to link and keeps `open-pr.sh`'s closing-link check quiet.
- **Assumption — deliver reports `check-scope: passed` without re-running the check,** because the spine reaches `open-pr.sh` only after `check-scope.sh` exits 0. `rad pr-body` runs it for real.
- **Assumption — test presence is read from the commit (`HEAD` or the branch tip),** not the working tree. An uncommitted test file is not in the PR, so it counts as missing.
- **Assumption — `MAX_COMMITS` is 100.**
- **Assumption — a failed input read degrades to an "unavailable" section instead of failing the run.** The reason is visible in the PR.
